## 主代理采纳与纠正

### 播放器报告

- 采纳：session/revision 贯穿命令与事件、统一协调模块、乱序/停止/EOF fake 测试、超时后禁止无管理地复用后端。
- **修正停止事实：** 当前 `PlayerHost::shutdown_worker` 已设置 `running=false`，并在 `tx.take()` 时发送 `Quit`；另起线程负责 join，超时才返回。不是“从未发 Quit”。真正问题是超时后宿主引用被清空，调用者不再持有可等待清理完成的 owner，最终 HWND 回收缺少明确路径。该风险不等于已复现设备继续播放。
- **不采纳“worker 自己销毁 HWND”的直接实现：** HWND 的线程归属必须遵守 Windows 规则，native teardown 完成后需要在创建窗口的线程执行销毁，不因转移所有权就能跨线程 DestroyWindow。
- 续播阈值分层：存储不足 5 秒不写；报告提到的播放页约 10 秒 seek 门槛属于另一层，不能合并为同一个常量。实施先写边界测试并决定是否保留。
- 报告提议先嵌入、再独立窗口；主方案采用独立窗口先验证已知封装，再补嵌入/精选交互实验，避免技术探针先背复杂合成成本。最终产品窗口策略仍未锁定。
- `--audio-file`、固定 2s/5s、10Hz 等是候选，不是已验证兼容性或性能要求，不直接写死到生产实现。

### 架构报告

- 采纳：深模块、少接口、单向依赖、双平台 CI、版本和许可证记录。
- **不采纳共写旧数据目录：** 新预览目录 + 一致副本导入是默认，以旧程序可安全回退为优先。不允许“一份 .bak + 同目录”替代并存设计。
- **不采纳“弹幕设置只对下次播放生效”的目标：** 它保留已知运行时不同步风险；主方案要求实时与持久化统一，并给出可见失败语义。
- 分出独立 Windows adapter 工程，防止 Infrastructure 直接包含 HWND/DPAPI 导致 Linux 测试被平台依赖污染。
- 不采纳“首次 C# 一律不写 schema 版本”：可以在独立新库维护明确迁移版本，只是不能复用旧版本 1 的含义或静默改写旧库。
- “Linux 不能还原 WinUI”不能从一次 TLS EOF 推导；准确结论是此次还原失败、没有进入 XAML 编译，完整构建留 Windows。
- 身份协议的 fixture、Cookie 解析和取消可以在 Linux 测；只有 DPAPI/平台集成需 Windows，不采用报告表格中的“登录/Cookie 不可测”笼统分类。
- 发现导航以当前 `discover-tabs` 实现和相关测试为准，README 的排行描述可能与当前 Tab 合并不同；M0 功能对照必须核实，不把报告的路由/命令计数当硬性产品契约。

### 数据安全报告

- 采纳：SQLite 快照/事务/幂等、Unix 秒与复合主键兼容、DPAPI 真机跨语言实验、响应及解压限额、图片 Cookie 隔离、写操作结果未知不重试。
- **设置白名单为 13 个 key，非报告所述 12 个**（当前 `commands/settings.rs::ALLOWED_KEYS`）；项目没有理由据此截断迁移字段。
- “代码未显式设置 PRAGMA”不等于没有 SQLite 的隐式事务或库默认 busy 行为；只把批量导入缺少整体事务作为已证源码问题。
- WAL/`.db-journal` 文件存在与否不是可靠进程存活/写锁检测；旧程序也不会因新程序发明命名 mutex 就自动配合。导入需显式关闭旧程序，结合一致快照与错误处理，不根据文件名猜安全。
- 备份使用 SQLite 一致快照，不直接复制正在写入的 `.db`；会话原子替换还需处理目标首次不存在、失败清理、备份 ACL 与保留策略。
- gzip/deflate 处理要同时限制原始与解压数据；`Take(limit)` 必须区分“到达上限”和“正常 EOF”，常用 limit+1 检测，不能把截断 JSON 误当有效响应。
- `-352/-412` 风控类响应不能当普通瞬态 GET 无限重试；应中止/冷却并给出可理解提示，不尝试绕过风控。
- Cookie 当前请求和重定向的具体转发行为须针对依赖版本测试；不把“包含重定向链所有 Set-Cookie”作为已证事实。
- DPAPI 以同用户同机兼容为正向测试；不要把跨机器一定失败作为普遍平台保证（例如配置/凭据漫游有额外因素）。跨用户拒绝用具体测试环境验证。
- 第三方包许可必须按固定版本核验，报告举例的许可证不能直接复制到最终清单；不因某组件有 GPL 文件就推断整个安装包统一 GPL。
